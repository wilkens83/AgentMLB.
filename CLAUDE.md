# MLB Analytics System - Claude Code Spec

You are an expert full-stack Python data engineer and MLB Statcast analyst working directly on a GitHub repository.

## Git & Repository Rules
1. **Single Branch Policy**: Always work directly on the `main` branch.
   - DO NOT create feature branches (e.g., `git checkout -b feature/...`).
   - Commit directly to `main` using descriptive semantic commit messages: `feat:`, `fix:`, `refactor:`, `test:`.
   - Ensure the working tree is clean and tests pass before committing.
2. **Secrets & Environment**: Never commit `.env` or plain-text credentials. Use environment variables for `SUPABASE_URL`, `SUPABASE_KEY`, and `DATABASE_URL`.

## Database Spec (Supabase / PostgreSQL)
- **Primary Table**: `statcast_pitches`
- **Dialect**: PostgreSQL (use `ILIKE` for case-insensitive matching, `DATE_TRUNC` for time series, `EXTRACT` for seasons).
- **Safety**: SQL queries generated by the agent must be strictly read-only (`SELECT` queries only).

## Statcast Domain Context
- `player_name`: Pitcher name (`'Last, First'`)
- `game_year`: Season (2021–2025)
- `pitch_type`: 2-letter pitch code (`FF`=4-Seam, `SL`=Slider, `CH`=Changeup, `CU`=Curveball, `SI`=Sinker, `FC`=Cutter, `ST`=Sweeper)
- `release_speed`: Velocity in MPH | `release_spin_rate`: Spin in RPM
- `launch_speed`: Exit velocity (MPH) | `launch_angle`: Launch angle (degrees)
- `launch_speed_angle`: Contact quality (6=Barrel, 5=Solid, 4=Flare, 3=Under, 2=Topped, 1=Weak)
- `plate_x`, `plate_z`: Horizontal and vertical location over home plate (feet)
- `events`: Outcome (`single`, `strikeout`, `walk`, `home_run`, etc.)

## Execution Loop & Checkpoints
- After completing a task node, write a checkpoint to `PROGRESS.md` before staging changes:
  1. Files created/modified.
  2. Test results.
  3. Next task.
- Commit to `main` immediately upon verifying each milestone.
